# `@frc2064/ui` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract Cacao's Material 3 Expressive design system into a standalone
`@frc2064/ui` package and convert Cacao to consume it, so every 2064 web app
shares one set of tokens, motion, and components.

**Architecture:** A new repo `FRC-2064/ui` ships *source* — no build step, no
`dist/`. It is itself a small SvelteKit app so that a demo route can render
every component in both themes, but what consumers import is `src/lib`.
Consuming apps own `svelte`, `tailwindcss`, and `lucide-svelte` as peers.
Cacao then deletes its local copies and imports from the package.

**Tech Stack:** Svelte 5 (runes), SvelteKit 2, Tailwind v4, TypeScript,
Vitest, lucide-svelte.

**Spec:** `docs/superpowers/specs/2026-08-31-frc2064-ui-library-design.md`

## Global Constraints

- **No library component may import from `$app/*`.** Astro renders Svelte
  components but not SvelteKit. Anything routing-aware takes props.
- **No build step.** The package exports `.svelte` and `.ts` from `src/lib`
  directly. Never add a `prepare` script or commit a `dist/`.
- `svelte`, `tailwindcss`, `lucide-svelte` are **peerDependencies**, never
  dependencies. One copy of Svelte in the tree is a correctness requirement.
- Library `ui.css` must **not** contain `@import "tailwindcss"` — the consumer
  owns that import.
- Existing Cacao behaviour must not change. The theme storage key stays
  `cacao_theme_v1` so no saved preference resets.
- Library repo path on this machine: `/home/levi/repos/robotics/ui`
  (sibling of `/home/levi/repos/robotics/cacao`).
- Package name: `@frc2064/ui`. Git tag for first release: `v0.1.0`.
- Node 26.8.1+ (`extra/nodejs`, not `cachyos-znver4/nodejs` — that build links
  a `libada.so.3` that no longer exists).

## A correction to the spec

The spec says `motion.ts`, `isActive`, and the theme store "move with their
unit tests". **Those tests do not exist** — Cacao has no `motion.test.ts`,
`nav.test.ts`, or theme test today. This plan therefore *writes* them, TDD,
as part of the extraction. The intent of the spec line is met; the wording
was optimistic.

- [ ] **Step 1: Write the failing test**

The property worth pinning is the one a future maintainer would break by
"tidying up": the spatial curves must be allowed to overshoot past 1, and the
effects curves must not. `motion.ts` says so in a comment; this makes it fail
loudly instead.

`src/lib/motion.test.ts`:

```ts
import { describe, expect, it } from 'vitest';
import {
  cubicBezier,
  dur,
  fastEffects,
  defaultEffects,
  slowEffects,
  fastSpatial,
  defaultSpatial,
  slowSpatial,
  listItem
} from './motion';

const sample = (easing: (x: number) => number) =>
  Array.from({ length: 101 }, (_, i) => easing(i / 100));

describe('cubicBezier', () => {
  it('pins both ends', () => {
    const ease = cubicBezier(0.42, 1.67, 0.21, 0.9);
    expect(ease(0)).toBe(0);
    expect(ease(1)).toBe(1);
  });

  it('inverts x accurately enough to be indistinguishable from the CSS curve', () => {
    // linear() is its own inverse, so any error shows up directly.
    const linear = cubicBezier(1 / 3, 1 / 3, 2 / 3, 2 / 3);
    for (const x of [0.1, 0.25, 0.5, 0.75, 0.9]) {
      expect(linear(x)).toBeCloseTo(x, 5);
    }
  });
});

describe('the two easing families', () => {
  it('lets the spatial curves overshoot, which is the whole point of them', () => {
    for (const easing of [fastSpatial, defaultSpatial, slowSpatial]) {
      expect(Math.max(...sample(easing))).toBeGreaterThan(1);
    }
  });

  it('never lets the effects curves overshoot', () => {
    // An opacity or colour that overshoots is a bug, not a bounce.
    for (const easing of [fastEffects, defaultEffects, slowEffects]) {
      expect(Math.max(...sample(easing))).toBeLessThanOrEqual(1);
    }
  });
});

describe('list presets', () => {
  it('reorders more slowly than it removes', () => {
    // Reordering is the change a user has to track with their eyes.
    expect(listItem.flip.duration).toBeGreaterThan(listItem.out.duration);
  });

  it('matches the CSS duration tokens', () => {
    expect(listItem.flip.duration).toBe(dur.defaultSpatial);
  });
});
```

```ts
/**
 * The script that stamps the stored theme onto `<html>` before first paint.
 *
 * It has to run before the browser paints anything, which means before the
 * bundle loads -- so it cannot import the theme store, and the validation
 * below is deliberately a duplicate of `createTheme`'s. Keep the two in step:
 * if they disagree, a corrupt stored value paints one theme and the store
 * swaps it a moment after hydration, which is the exact flash this exists to
 * prevent.
 *
 * Astro can emit the return value inline:
 *
 *     <script is:inline set:html={prepaint('site_theme')}></script>
 *
 * SvelteKit's app.html is static and cannot call a function, so a SvelteKit
 * app keeps a literal copy in its own app.html. That duplication is real; the
 * README carries the canonical snippet.
 */
export function prepaint(key: string): string {
  return `try{var t=localStorage.getItem(${JSON.stringify(key)});if(t==='light'||t==='dark'){document.documentElement.setAttribute('data-theme',t)}}catch(e){}`;
}
```

- [ ] **Step 4: Write `theme.svelte.ts`**

```ts
export type ThemePreference = 'system' | 'light' | 'dark';

export interface ThemeOptions {
  /** localStorage key. Give each app its own so two on one origin cannot collide. */
  key: string;
}

/**
 * Theme preference, persisted to localStorage and mirrored onto
 * `<html data-theme>`. 'system' clears the attribute so the
 * prefers-color-scheme block in ui.css takes over.
 *
 * The environment check is `typeof document`, not SvelteKit's `browser`: this
 * has to run inside an Astro island too, where `$app/environment` does not
 * exist.
 */
class ThemeStore {
  preference = $state<ThemePreference>('system');
  #key: string;

  constructor(options: ThemeOptions) {
    this.#key = options.key;
    if (typeof document === 'undefined') return;
    let stored: string | null = null;
    try {
      stored = localStorage.getItem(this.#key);
    } catch {
      // Private mode, or storage disabled. System is a fine answer.
    }
    if (stored === 'light' || stored === 'dark') this.preference = stored;
  }

  /** The theme actually being rendered, resolving 'system' against the OS. */
  get resolved(): 'light' | 'dark' {
    if (this.preference !== 'system') return this.preference;
    if (typeof window === 'undefined') return 'light';
    return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
  }

  set(preference: ThemePreference) {
    this.preference = preference;
    if (typeof document === 'undefined') return;

    try {
      if (preference === 'system') {
        document.documentElement.removeAttribute('data-theme');
        localStorage.removeItem(this.#key);
      } else {
        document.documentElement.setAttribute('data-theme', preference);
        localStorage.setItem(this.#key, preference);
      }
    } catch {
      // The attribute is what the user sees; storage failing is survivable.
    }
  }

  toggle() {
    this.set(this.resolved === 'dark' ? 'light' : 'dark');
  }
}

export type { ThemeStore };

export function createTheme(options: ThemeOptions): ThemeStore {
  return new ThemeStore(options);
}
```

Note the `set` body now guards `removeAttribute` inside the same `try` as
storage, which Cacao's original did not — a storage throw used to leave the
attribute unchanged. That is a fix, not a port error.

`src/lib/actions/pill.ts`:

```ts
/**
 * Keeps a `.segmented-indicator` sitting under whichever `.segmented-item`
 * is active inside `seg`.
 *
 * CSS cannot animate a background from one sibling to another, so the active
 * fill is a separate absolutely-positioned element whose offset and width are
 * measured here and written as custom properties. Everything else -- the
 * easing, the rounding, the colour -- is CSS.
 *
 * Call it from an `$effect` that reads whatever makes the active item change,
 * and return the cleanup:
 *
 *     $effect(() => {
 *       value; options.length;
 *       if (!segEl || !indEl) return;
 *       return trackPill(segEl, indEl, (ready) => (indReady = ready));
 *     });
 */
export function trackPill(
  seg: HTMLElement,
  ind: HTMLElement,
  setReady: (ready: boolean) => void
): () => void {
  const sync = () => {
    const active = seg.querySelector<HTMLElement>('.segmented-item.is-active');
    // Zero width means the control is display:none. Leave the pill hidden
    // until it has real geometry to sit on, rather than parking a 0px sliver
    // at the origin.
    if (!active || active.offsetWidth === 0) {
      setReady(false);
      return;
    }
    ind.style.setProperty('--ind-x', `${active.offsetLeft}px`);
    ind.style.setProperty('--ind-w', `${active.offsetWidth}px`);
    // `.is-ready` is what carries the transition, so granting it a frame after
    // the offsets land keeps the pill from sliding in from the left edge on
    // first paint.
    requestAnimationFrame(() => setReady(true));
  };

  sync();

  // Covers viewport resizes, a tab appearing, and late webfont loads reflowing
  // the labels -- all of which move the target out from under it.
  const ro = new ResizeObserver(sync);
  ro.observe(seg);
  return () => ro.disconnect();
}
```

```ts
export type ToastType = 'success' | 'info' | 'error';

export interface Toast {
  text: string;
  type: ToastType;
}

/** Long enough to read a sentence, short enough not to sit over the UI. */
const DISMISS_AFTER_MS = 4000;

class Toasts {
  current = $state<Toast | null>(null);
  #timer: ReturnType<typeof setTimeout> | null = null;

  show(text: string, type: ToastType = 'success') {
    // Cancelling the previous timer is what stops an earlier toast from
    // dismissing a later one. Matching on text instead -- which is what this
    // replaces -- breaks the moment the same message is shown twice, and two
    // identical messages in a row is what a retry looks like.
    if (this.#timer !== null) clearTimeout(this.#timer);
    this.current = { text, type };
    this.#timer = setTimeout(() => {
      this.current = null;
      this.#timer = null;
    }, DISMISS_AFTER_MS);
  }

  dismiss() {
    if (this.#timer !== null) clearTimeout(this.#timer);
    this.#timer = null;
    this.current = null;
  }
}

/**
 * One toast at a time, app-wide. A queue would be worse: a burst of failures
 * would make the user wait out a backlog of messages about the same thing.
 */
export const toasts = new Toasts();
```

```ts
// lucide-svelte 0.475 still emits legacy class components, so icons are typed
// as ComponentType rather than Svelte 5's Component.
import type { ComponentType } from 'svelte';

export interface NavItem {
  href: string;
  label: string;
  icon?: ComponentType;
  /**
   * A resolved count, not a key. What a badge counts is the app's business --
   * pending expenses in one app, unread messages in the next.
   */
  badge?: number;
}

function normalise(pathname: string): string {
  return pathname.replace(/\/+$/, '') || '/';
}

/**
 * Exact match, both sides normalised.
 *
 * Every nav destination is a flat top-level route with no sibling sub-routes,
 * so there is no need for a prefix-matching variant. Trailing slashes are
 * stripped because SvelteKit and Astro disagree about them and the same nav
 * has to light up under both.
 */
export function isActive(pathname: string, href: string): boolean {
  return normalise(pathname) === normalise(href);
}
```

```ts
interface NavSource {
```

```ts
/**
 * The finished list the shell renders: admin-only entries filtered out for
 * everyone else, and each badge resolved from a key to a live count.
 *
 * The library's NavItem carries a number because what a badge counts is this
 * app's business, not the design system's.

export function navItems(): NavItem[] {

      href,
      label,
      icon,

  );
}
```
